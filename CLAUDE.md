# NetRadiant-custom: Silent Hill 1 style town level

This fork extends the editor and q3map2 to author a **Silent Hill 1 style town level for Quake 3**, not a new game. The design plan is `docs/pbr-plan/pbr-plan.tex` (revision 8). It is the source of truth; the section numbers below (§) refer to it. Build the PDF with `latexmk -pdf` in `docs/pbr-plan/`.

## Targets (plan §1)

1. **Authoring:** NetRadiant-custom under `Q3.game`, with PBR materials written as text. q3map2 compiles.
2. **Stock:** ioquake3 with `cl_renderer opengl1` or `opengl2` at default cvars runs the same pk3 as plain lightmapped Quake 3 content, so the level can be uploaded to lvlworld.com. It uses **no rend2 features** (no normal/specular maps, `r_pbr` or HDR lighting files), and should look as faithful to the enhanced target as a lightmap allows. There is no original look to reproduce: the shipped pk3 only has to run on vanilla and carry everything `renderer_sh` needs. When choices tie, the easiest path in the editor wins.
3. **Enhanced:** the customised ioquake3 (`../ioq3-custom/ioq3`) with `renderer_sh` (the existing sh-renderer, `../ioq3-custom/sh-renderer`, grown into an ioquake3 renderer module loaded by `cl_renderer sh`) runs the same pk3. PBR levels are developed for this target.

Original non-PBR Quake 3 levels keep running on `opengl2`. Every enhancement must be ignored by the stock target (plan §Compatibility contract).

## Ground rules

- **Materials** are stock `scripts/*.shader` files with vanilla Quake 3 stages only. All PBR data goes in top-level `qer_pbr_*` keywords: `qer_pbr_normal`, `qer_pbr_metallicRoughness`, `qer_pbr_occlusion`, `qer_pbr_roughnessFactor`, `qer_pbr_metallicFactor`, `qer_pbr_baseColorFactor`, `qer_pbr_emissiveStrength`. Emissive uses an additive stage. No rend2 keywords (`stage normalMap`, `specularMap`, `roughness`, ...): they make `renderergl1` reject the shader. Never name an image `<base>_n`, `_nh` or `_s`, because rend2 auto-loads those. See §Material authoring.
- **Lights** are the editor's physical light entities, unchanged from Stage 1/2: `light` (point, `intensity` flux, `radius` cutoff), `light_spot` (`cone`, `cone_inner`, `target` or `angles`) and `light_sun` (irradiance, one honoured), with `_shadows` on spots and suns. Point lights never cast. Revision 7 adds `light_area` (a one-sided rectangle: `width`, `height`, `angles` normal, `intensity` radiance, `_frustum` shadow half-angle, LTC shading) attached to a static emissive quad, and `_proxy 1` on a `light`/`light_spot` standing in for any other emitter. Their intensity is derived from the emitter's shader (strength × `rgbGen const` × mean linear texel), and the bake ignores both because the surface's own emission already bakes. `Q3.game` gets them through the overlay in `setup/data/gamepacks/pbr/` (`games/Q3.game` with `entities="pbr"`, `Q3.game/baseq3/_pbr_lights.ent`); install it with `sh install-gamepack.sh setup/data/gamepacks/pbr install/gamepacks` after the downloaded packs. The editor preview, sh-baker and `renderer_sh` share this model (§Units), documented in `setup/data/gamepacks/pbr/README.md` with the shading and shadow constants. The overlay's build menu adds three "Town" builds with the stock check's compile stages, differing only in the light stage: "Town (draft)" `-light -shbake -shsamples 128`, "Town (pre-release)" `-shsamples 512 -super 2` and "Town (final)" `-shsamples 2048 -super 2` (exact samples per point; times and noise in the gamepack README). Stock ioquake3 prints `light_spot`/`light_sun`/`light_area` "doesn't have a spawn function" once per entity; that is harmless, and the stock check allowlists those three lines.
- **The vanilla lightmap** is written by sh-baker through `q3map2 -light -shbake` (B5) from the same lights; the Town builds and the stock check (at the defaults, 128 samples and `-super 1`) use it. Plain `-light` still makes the old placeholder, which isn't expected to match the preview.
- **Packaging:** one pk3 per level (BSP, shaders, base textures, lightmaps, PBR maps, the SH side file `maps/<name>/<name>.shsf`).
- **`pbr.game` and the `.mtr` language are retired (A7); materials are `scripts/*.shader` only.** The `pbr` entity module and the overlay stay, because `Q3.game` uses them.
- `ioq3-map-exporter` and `ioq3-materialize` (in `../ioq3-custom`) were an unsuccessful earlier attempt and are not part of the pipeline. The same goes for sh-renderer's glTF path (exporter → glTF → sh-renderer): it is deleted in C0, and `renderer_sh` keeps no compatibility with it.
- **Editor changes go through openspec changes** (`openspec/`), as the archived stage1/stage2 did.
- **sh-baker changes go as PRs to `github.com/DaviesX/sh-baker`**, which the user reviews and merges. Ask before pushing or opening any PR.
- **sh-renderer changes go as PRs to `github.com/DaviesX/sh-renderer`**, under the same rule: the user reviews and merges, and you ask before pushing or opening any PR.
- **Once task A5 exists, every task's exit criterion includes the stock check.**
