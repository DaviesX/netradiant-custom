# NetRadiant-custom: Silent Hill 1 style town level

This fork extends the editor and q3map2 to author a **Silent Hill 1 style town level for Quake 3**, not a new game. The design plan is `docs/pbr-plan/pbr-plan.tex` (revision 7). It is the source of truth; the section numbers below (§) refer to it. Build the PDF with `latexmk -pdf` in `docs/pbr-plan/`.

## Targets (plan §1)

1. **Authoring:** NetRadiant-custom under `Q3.game`, with PBR materials written as text. q3map2 compiles.
2. **Stock:** ioquake3 with `cl_renderer opengl1` or `opengl2` at default cvars runs the same pk3 as plain lightmapped Quake 3 content, so the level can be uploaded to lvlworld.com. It uses **no rend2 features** (no normal/specular maps, `r_pbr` or HDR lighting files), and should look as faithful to the enhanced target as a lightmap allows. There is no original look to reproduce: the shipped pk3 only has to run on vanilla and carry everything `renderer_sh` needs. When choices tie, the easiest path in the editor wins.
3. **Enhanced:** the customised ioquake3 (`../ioq3-custom/ioq3`) with `renderer_sh` (the new sh-renderer, `../ioq3-custom/sh-renderer`) runs the same pk3. PBR levels are developed for this target.

Original non-PBR Quake 3 levels keep running on `opengl2`. Every enhancement must be ignored by the stock target (plan §Compatibility contract).

## Ground rules

- **Materials** are stock `scripts/*.shader` files with vanilla Quake 3 stages only. All PBR data goes in top-level `qer_pbr_*` keywords: `qer_pbr_normal`, `qer_pbr_metallicRoughness`, `qer_pbr_occlusion`, `qer_pbr_roughnessFactor`, `qer_pbr_metallicFactor`, `qer_pbr_baseColorFactor`, `qer_pbr_emissiveStrength`. Emissive uses an additive stage. No rend2 keywords (`stage normalMap`, `specularMap`, `roughness`, ...): they make `renderergl1` reject the shader. Never name an image `<base>_n`, `_nh` or `_s`, because rend2 auto-loads those. See §Material authoring.
- **Lights** are the editor's physical light entities, unchanged from Stage 1/2: `light` (point, `intensity` flux, `radius` cutoff), `light_spot` (`cone`, `cone_inner`, `target` or `angles`) and `light_sun` (irradiance, one honoured), with `_shadows` on spots and suns. Point lights never cast. Revision 7 adds `light_area` (a one-sided rectangle: `width`, `height`, `angles` normal, `intensity` radiance, `_frustum` shadow half-angle, LTC shading) attached to a static emissive quad, and `_proxy 1` on a `light`/`light_spot` standing in for any other emitter. Their intensity is derived from the emitter's shader (strength × `rgbGen const` × mean linear texel), and the bake ignores both because the surface's own emission already bakes. `Q3.game` gets them through the overlay in `setup/data/gamepacks/pbr/` (`games/Q3.game` with `entities="pbr"`, `Q3.game/baseq3/_pbr_lights.ent`); install it with `sh install-gamepack.sh setup/data/gamepacks/pbr install/gamepacks` after the downloaded packs. The editor preview, sh-baker and `renderer_sh` share this model (§Units), documented in `setup/data/gamepacks/pbr/README.md` with the shading and shadow constants. The overlay's build menu adds three "Town" builds with the stock check's compile stages, differing only in the light stage: "Town (draft)" `-light -shbake -shsamples 128`, "Town (pre-release)" `-shsamples 512 -super 2` and "Town (final)" `-shsamples 2048 -super 2` (exact samples per point; times and noise in the gamepack README). Stock ioquake3 prints `light_spot`/`light_sun`/`light_area` "doesn't have a spawn function" once per entity; that is harmless, and the stock check allowlists those three lines.
- **The vanilla lightmap** is written by sh-baker through `q3map2 -light -shbake` (B5) from the same lights; the Town builds and the stock check (at the defaults, 128 samples and `-super 1`) use it. Plain `-light` still makes the old placeholder, which isn't expected to match the preview.
- **Packaging:** one pk3 per level (BSP, shaders, base textures, lightmaps, PBR maps, the SH side file `maps/<name>/<name>.shsf`).
- **`pbr.game` and the `.mtr` language are retired (A7); materials are `scripts/*.shader` only.** The `pbr` entity module and the overlay stay, because `Q3.game` uses them.
- `ioq3-map-exporter` and `ioq3-materialize` (in `../ioq3-custom`) were an unsuccessful earlier attempt and are not part of the pipeline.
- **Editor changes go through openspec changes** (`openspec/`), as the archived stage1/stage2 did.
- **sh-baker changes go as PRs to `github.com/DaviesX/sh-baker`**, which the user reviews and merges. Ask before pushing or opening any PR.
- **Once task A5 exists, every task's exit criterion includes the stock check.**

## Task sequence

Three tracks can run in parallel. Within a track, do the tasks in order. `needs:` lists dependencies on other tracks.

### Track B: SH baking in q3map2

- ~~**B1** sh-baker PR: library boundary.~~ Dropped: q3map2 includes sh-baker's `src/` headers directly and links its `libsh_baker.so`, so no separate public header is needed. (§4.2)
- [x] **B2** sh-baker PRs: the q3map2 input contract, as a stack of seven PRs (openspec change `sh-baker-q3map2-input`). An owned material-layer model in `material.h` (no tinygltf in the headers q3map2 includes), a q3map2 loader TU (`loader_q3map2.{h,cpp}`: checked tracing geometry, shared MikkTSpace tangents), and the point bake: one `BakeSHLightMap` call over caller-supplied points. No page model in sh-baker: q3map2 owns the luxel mapping. (§4.2)
- [x] **B2b** sh-baker PR: NEE shadow rays honour alpha the way the tracer's indirect rays do, so fences and leaf cards cast through their cut-outs. Kept out of B2 because it changes bake output. (§4.2)
- [x] **B3** sh-baker PR: progress, cancel and done callbacks on the single bake call, which already builds the BVH and light trees once. (§4.2)
- [x] **B4** q3map2: the SH side-file format as the q3map2 extension (`tools/quake3/q3map2/q3map2_extension.{h,cpp}`, openspec change `q3map2-sh-extension`): L0–L2 and visibility per page plus the solid hull mesh (§3.5), with an optional `.hdr` L0 dump for inspection, tested by `make test-q3map2-extension`. sh-baker returns results per luxel and is unchanged; q3map2 assembles the pages and hulls. No rend2 layout. (§4.2)
- [x] **B5** q3map2 `-shbake`, an option of `-light` (`light_sh.cpp`, opt-in `SH_BAKER=1` in the Makefile, which adds `tools/sh-baker/src` to the include path and links the submodule's Release `libsh_baker.so`; `light_sh.cpp` alone is compiled with `-march=native` to match the library's Eigen alignment). It runs after `MapRawLightmap` and replaces `IlluminateRawLightmap`'s lighting math: q3map2 supplies its own points (super-luxels with `-super N` for anti-aliasing, one full-sphere point per grid point, vertices), adds its draw surfaces through sh-baker's q3map2 loader and solid brush hulls as occluders. Two independent `BakeSHLightMap` calls over the same points: the **full bake** writes `SHCoeffs::irradiance` into the BSP lightmap pages and vertex colours, and a one-light fit of the grid SH into the light grid (encoding chosen to look good on vanilla); the **indirect bake** (`indirect_only`) writes the SH side file: luxel pages, hull mesh and an SH grid (one probe per BSP grid point, with a valid flag). Both run by default; `-shnofull` writes neutral byte 64 to the lightmap pages and vertex colours and neutral ambient (63) with no directed light to the grid, `-shnoindirect` writes no side file. Every light is shadowed in the bake (sh-baker has no per-light switch); the preview and `renderer_sh` keep the caster rule. B5 writes no rend2 HDR lighting files (B6 dropped). q3map2's shader parser learns `qer_pbr_*` and the editor's caster rule. `light_area` and `_proxy` lights are skipped without a warning, and an emissive surface with no attached light gets one warning per shader (revision 7). q3map2 stays the host. sh-baker PRs: range and smoothstep (#65), all-direct `indirect_only` (#66), `SurfacePoint::full_sphere` for grid points (#67), and `confidence_threshold` 0 for an exact sample count (#68), which q3map2 always passes, so `-shsamples N` is exact. Measured times, the quality presets, the encoding constants and the known gaps are in §4.3. needs: B2b, B4, A5. (§4.2, §4.3)
- ~~**B6** q3map2 `-shbake`: opengl2 HDR lighting files (`lm_%04d.hdr`, `vertlight.raw`, `lightgrid.raw`).~~ Dropped (2026-11-20): rend2 only promotes to HDR lightmaps when `lm_0000.hdr` is a loose homepath file (`FS_FileExists_HomeData` searches no pk3), and its size check counts the header, so a shipped pk3 never uses `lm_*.hdr`. opengl2 applies no sRGB encode, so the two `.raw` files (which do load from a pk3) would only add sub-byte precision to vertex colours and the grid in B5's encoding. opengl2 keeps the BSP bytes. (§Current state, rend2 facts)
- [ ] **B7** sh-baker PRs: path guiding for point bakes (GEMINI.md Phase 10, adapted so q3map2 owns the mapping).
